根因:三套图标体系并存

同一个功能在代码里有两套图标,视觉不统一,是"看不出功能"的系统性来源。

现状: 新代码用统一 SVG 库 Icons.tsx(A,推荐);几乎所有 Settings / Dialog / 选择器仍用 VS Code 的 Codicon 字体(B,~250 处);文件树用彩色文件 SVG(C,装饰)。
建议方向(§6 详述): 把 Codicon 与一次性内联 SVG 收敛到 Icons.tsx 单一来源,"齿轮/机器人/刷新"只保留一套,顺手统一 size token(当前 12/14/15/16/20/24 混用)。

输入框与对话区

最高频 · 用户每天都在点

这一组是"误操作重灾区":刷新 vs 回退、层叠 vs 缓存,语义全靠猜。

"对话回退一步",与刷新彻底区分
理由: 把"刷新"语义换成"消息撤回"。气泡表明对象是对话,左箭头表明方向是回退。

可选下一步:体系统一

上面是"换图标"的最小修复;真正治本是把三套体系收敛为一套。这步可独立排期,不影响上面的图标替换。

收敛目标: 所有图标统一走 Icons.tsx 单一来源 —— 删除 ~250 处 Codicon 字体引用(及其 ttf 依赖),回收各组件里一次性内联的 CopyIcon / ArrowRightIcon / BrainIcon 等重复定义,建立 size token(如 sm=14 / md=16 / lg=20)。
收益: 同功能只剩一套图标(齿轮/机器人/刷新不再各有两版),包体更小,主题与无障碍(color-contrast)集中可控。
风险: Codicon 覆盖面广,建议按 Settings → Dialog → Selectors 分批迁移,每批配可视化回归。
