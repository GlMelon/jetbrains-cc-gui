5F-A：颜色与状态文案微调

目标是让 Provider 图标保留识别度，状态文字保持“原生、克制、低干扰”。下面重点对比状态文案、颜色饱和度和是否只在选中标签强调。

A：中文短词 + 柔和语义色
推荐

文案最直观：运行中 / 已完成 / 排队中。颜色比之前更柔和，避免太亮。

Codemoss Chat
CxAI1运行中×
Cl修复 MCP 网关已完成×
Oc响应优化排队中×
ClAI4×
建议色：运行中 #8FBFFF，已完成 #94D9A8，排队中 #E1B56F。
B：中文动作态 + 更低对比

状态像 IDE 辅助信息，不强行吸引注意力。适合不希望 tab 太花。

Codemoss Chat
CxAI1生成中×
Cl修复 MCP 网关完成×
Oc响应优化等待×
ClAI4×
文案更短，但“等待”不如“排队中”明确。
C：英文短码 + 技术感

更像开发工具状态栏：RUN / DONE / WAIT。紧凑、国际化友好。

Codemoss Chat
CxAI1RUN×
Cl修复 MCP 网关DONE×
Oc响应优化WAIT×
ClAI4×
更“IDE”，但中文环境下不如中文自然。
D：只强调当前选中标签

未选中的状态文字全部中性灰；只有当前选中的进行中标签使用蓝色。

Cl修复 MCP 网关已完成×

最不打扰，但多个后台任务状态不够醒目。
E：文字中性 + Provider 边框表达状态

状态颜色不放在文字上，而是轻轻描边 provider 图标，更接近原生图标体系。

Cl修复 MCP 网关已完成×

视觉很稳，但状态依赖图标边框，识别速度略慢。
F：中性文字 + 极小状态符号

状态文字基本中性，只在前面加很小的 ● / ✓ / …，兼顾色弱可读性。

Codemoss Chat
CxAI1运行中×
Cl修复 MCP 网关已完成×
Oc响应优化排队中×
ClAI4×
最稳健，但符号会让 tab 信息稍多。
文案推荐PROCESSING 用“运行中”，COMPLETED 用“已完成”，QUEUED 用“排队中”，IDLE 不显示。
颜色推荐用柔和语义色：蓝 #8FBFFF、绿 #94D9A8、橙 #E1B56F，避免高饱和抢眼。
不建议“进行中”略长且偏流程；“生成中”只适合模型回复，不适合工具调用/执行命令。
最终建议选 A：中文短词 + 柔和语义色。最清晰，也最贴近现有插件的深色 IDE 风格。
