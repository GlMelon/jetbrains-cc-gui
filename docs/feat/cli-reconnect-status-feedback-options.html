问题背景

网络波动等原因触发 CLI 重连时,前端 phase 一直停在 understanding, 用户只看到静态的"等待模型响应"干等 —— 后台其实在按指数退避自动重试 (message-sender.js: AUTO_RETRY_CONFIG,maxRetries:3), 前端也已备好 retrying / streamStalledRetrying / apiRetry 文案却未接到卡片上。 直到最终重试耗尽,才弹出红色 provider-error-block。目标:重连第 1 次就给可见提示,最终失败逻辑不变。

卡内琥珀提示 · 最小侵入

改动: AssistantResponseStatus.tsx 增 phase reconnecting 文案: 复用 chat.retrying 成本: ★☆☆

✓ 优点

  • 改动最小,延续现有紫青卡片视觉
  • 不动消息流布局,只在卡内追加一行
  • 文案 key 已存在,基本零新增

✗ 取舍

  • 提示较"安静",注意力不强
  • 无"取消等待"等行动入口
  • 5 次进度只是文字计数,无视觉进度
方案 B

独立重连通知条 + 进度 · 推荐

在状态卡正下方插入一条独立的琥珀色重连条(介于"正常等待"与"红色致命错误"之间的视觉等级):重连图标 + "连接中断,正在自动重连" + 5 段进度 + 倒计时环 + "停止等待"按钮。成功则变绿淡出,失败累积成红色原错误卡。

改动: 新增 ReconnectNotice 子组件 + phase reconnecting 文案: 新增 3 条(复用 streamStalledRetrying 语义) 成本: ★★☆

✓ 优点

  • 视觉等级清晰:琥珀(重连中)≠ 红(致命),不吓人
  • 有"停止等待"行动入口,用户可主动终止
  • 进度点 + 倒计时环,全程知情
  • 成功有正向反馈(变绿淡出),缓解焦虑

✗ 取舍

  • 需新增一个子组件,改动比 A 大
  • 消息流多一条元素,需处理淡出时机
  • 倒计时环需前端按指数退避推算
实现要点: 后端 message-sender.js 每次重试前下发一条 reconnecting 事件(含 attempt/max/nextDelayMs),前端 streamingCallbacks 转发到 AssistantResponseStatus,新增 ReconnectNotice 子条渲染。成功发 reconnectResolved 触发变绿淡出。
方案 C

重试时间线 · 信息密集

把现有"· 12s"计时升级为一条重试时间线:5 个节点标记每次重试结果(进行中琥珀脉冲 / 失败灰✕ / 待重试灰),可展开看每次的时间戳与错误摘要。全程透明,排查友好。

改动: AssistantResponseStatus.tsx 增时间线子区 文案: 复用 retrying + 新增节点态 成本: ★★★
